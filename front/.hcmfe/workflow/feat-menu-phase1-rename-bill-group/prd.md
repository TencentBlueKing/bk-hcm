## 一、背景与目标

现网 HCM（`<DEPLOY_HOST>`）左侧导航要按四期方案整合，本期是第一期，只做两件事：两个一级菜单更名，以及把「账号管理」下现有的账单类入口收进一个二级分组。

- 「资源管理」「账号管理」这两个名称与总规里的「业务资源」「资源运营」不一致，用户按新口径找不到入口。
- 「账号管理」下现在可进入的是「云账号管理」和「云账单管理」，它们是可点击菜单而不是分组。本期把它们收进二级分组「云账单管理」。
- 先把名称与账单类入口的层级对齐总规，后面三期在这个结构上继续加菜单。
- 目标用户：已登录、且原本就能看到这些菜单的现网用户。
- 本期不新增页面、不新增查询、不新增接口、不新增业务数据。

## 二、用户故事

1. 作为原来能看到「资源管理」的登录用户，我想要在原位置看到一级菜单「业务资源」，以便按总规名称进入原来的业务资源功能，且其下子菜单仍在。
2. 作为原来能看到「账号管理」的登录用户，我想要在原位置看到一级菜单「资源运营」，以便按总规名称进入原来的账号与账单功能。
3. 作为原来能看到「账号管理」下云账号管理或云账单管理的登录用户，我想要在「资源运营」下的二级分组「云账单管理」里看到这两个菜单，以便在分组中进入原来的页面，而分组标题本身不打开页面。
4. 作为通过旧书签或旧页面地址进入的用户，我想要仍然打开原来的页面，以便更名和降级之后已保存的入口不用更换。

|------|---------|--------|

| F-002 | 一级菜单「账号管理」显示名改为「资源运营」，在顶栏中的位置不变 | P0 |
| F-003 | 在「资源运营」下新增二级分组「云账单管理」，该二级仅为分组标题，不是菜单项 | P0 |
| F-004 | 将现有「云账号管理」「云账单管理」降为该分组下的三级菜单项，名称不变、落地页面不变 | P0 |
| F-005 | 「账号管理」下没有其它可见子菜单，因此不另起第二个二级分组；「资源运营」下不保留任何可点击的二级菜单项 | P0 |

### F-001 资源管理更名为业务资源

- **输入**：用户打开左侧导航。
- **行为**：该一级菜单显示为「业务资源」；其下二级分组与三级菜单项的名称、层级、相对顺序全部不变。
- **本期保持的现有结构**：
  - 分组「资源」：主机、硬盘、VPC、子网、弹性 IP、网络接口、路由表、安全组、负载均衡、证书托管
  - 分组「其他」：单据管理、任务管理、操作记录
  - 分组「账号」：云账号管理
  - 分组「回收站」：回收站
- **边界**：
  - 只改这一级的显示名称。
  - 「镜像」不在侧栏菜单中，本期不把它加进菜单。
  - 「业务资源 → 账号 → 云账号管理」与「资源运营」下的「云账号管理」是两处入口，本期只改名，不搬迁、不合并业务资源这一处。
- **异常**：用户原本看不到「资源管理」→ 更名后仍看不到「业务资源」。

### F-002 账号管理更名为资源运营

- **输入**：用户打开左侧导航。
- **行为**：该一级菜单显示为「资源运营」，它与其它一级菜单的左右顺序不变。
- **异常**：用户原本看不到「账号管理」→ 更名后仍看不到「资源运营」。

### F-003 新增二级分组「云账单管理」

- **输入**：用户进入「资源运营」。
- **行为**：
  1. 侧栏出现二级分组标题「云账单管理」。
  2. 本期每一个二级都只是分组名称，形态与「业务资源」现有分组一致，点击分组不打开页面。
  3. 可进入的页面只放在分组下的三级菜单项。
- **边界**：分组名称就是「云账单管理」，与其下同名的三级菜单项并存；「资源运营」下不保留可点击的二级菜单项。
- **异常**：用户看不到该分组下任何三级菜单 → 不因新增分组而获得新页面。

### F-004 现有账单菜单降为三级菜单项

- **输入**：用户查看「资源运营 → 云账单管理」。
- **行为**：
  1. 当前「账号管理」侧栏中的「云账号管理」「云账单管理」移到该分组下，作为三级菜单项。
  2. 名称不变，进入后打开的仍是原来的页面。
  3. 「云账单管理」页面内部的页签不是侧栏菜单，仍留在该三级菜单项对应的页面里。
- **边界**：父单列出的第三个账单类菜单项不在本分支的菜单注册范围内（该菜单项在不同构建变体下存在与否不一致），本期不新增；三级「云账单管理」与二级分组同名，两处都保留。
- **异常**：用户原来看不到其中某一项 → 调整后仍看不到那一项。

### F-005 没有其它子菜单时不另起分组

- **行为**：
  1. 按本分支的菜单注册数据，「账号管理」下没有这两项以外的可见子菜单。
  2. 因此「资源运营」下只有「云账单管理」一个二级分组，不把空层级留成可点击菜单。
  3. 若现网实际另有可见子菜单，不为它们保留可点击的二级菜单项，而是按「业务资源」的形式另起二级分组名称，再在分组下挂三级菜单项。
- **边界**：不把其它子菜单直接塞进「云账单管理」分组，除非它们本就属于账单这一类；隐藏的非菜单页面不升成侧栏菜单。
- **异常**：原来不可见的入口 → 仍然不可见。

### F-006 一级菜单顺序不变

- **行为**：一级菜单从左到右的顺序与现网一致（现网顺序：资源管理、服务请求、资源接入、账号管理、平台管理），仅把其中两个显示为「业务资源」「资源运营」。
- **边界**：不新增、不删除、不重排其它一级菜单。
- **异常**：某个一级菜单因权限本就不显示 → 本期不改变它的显隐。

### F-007 旧入口继续可用

- **行为**：旧页面地址与书签仍打开原来的页面；查看权限沿用原菜单权限，不放宽也不收紧。
- **边界**：本期不提供跳转提示，也不下线旧地址。
- **异常**：旧地址对应页面本就不存在或用户无权限 → 保持原有失败表现，不新增错误文案。

## 四、业务规则

- **R-001**：本期所有二级都只是分组名称，点击不打开页面，形态与「业务资源」现有分组一致。
- **R-002**：二级分组与其下三级菜单项同时使用「云账单管理」这一名称。
- **R-003**：降级范围仅限本分支「账号管理」侧栏中真实注册的「云账号管理」「云账单管理」；父单列出的第三个账单类菜单项不在本分支注册范围内，本期不新增。菜单项集合随构建变体不同，核对基准一律是当前分支的菜单注册数据，不按父单文字推断。
- **R-004**：「资源管理」只改一级名称，其下「资源 / 其他 / 账号 / 回收站」四个分组及内部菜单项不动。
- **R-005**：一级菜单左右顺序冻结。
- **R-006**：旧页面地址与书签必须继续打开原页面。
- **R-007**：本期没有跳转页，也没有菜单下线等待期。
- **命名规则**：只使用「业务资源」「资源运营」「云账单管理」「云账号管理」以及业务资源下原有分组名 / 菜单名，不使用别名。
- **权限规则**：沿用各菜单现有查看权限；不新增、不合并、不拆分权限项；无权限用户不得通过新分组名称看到原本不可见的页面。

## 五、非功能需求

- **性能**：本期不新增页面和查询，不单列响应时间、并发与容量指标。
- **安全与权限**：查看权限与更名前完全一致。
- **兼容性**：浏览器范围与现网一致；旧页面地址保持可用，等价于入口向后兼容。
- **可用性**：沿用现网导航可用性，不单列 SLA；旧地址必须继续打开原页面。

## 七、边界范围

### 本期包含

- 一级菜单「资源管理」更名为「业务资源」
- 一级菜单「账号管理」更名为「资源运营」
- 在「资源运营」下新增只作分组名称的二级「云账单管理」
- 将现有「云账号管理」「云账单管理」降为该分组下的三级菜单项
- 旧页面地址、书签与原查看权限保持可用

### 本期不包含

- 第二期：新增「云资源 / 资源纳管」，以及「资源接入」的迁移、跳转与下线
- 第三期：新增「工作台」及个人事务、公共事务
- 第四期：迁移并删除「服务请求」
- 调整一级菜单的左右顺序
- 调整「业务资源」下现有分组和菜单项
- 新增父单列出、但本分支未注册的第三个账单类菜单项
- 把其它子菜单留成可点击的二级菜单项，或塞进「云账单管理」分组
- 修改页面地址，或让旧地址失效
- 新增、合并或拆分查看权限
- 为任何二级分组提供独立页面

## 九、约束

- 本期不指定实现方式，变更限于导航的展示名称与层级；具体落码方案在 coding 阶段确定。
- **落码基线**：当前分支（master 基线）上的现存菜单实现。此前一次整体菜单重构未合入，不作为本期基线，也不复用其结构。
- **变体口径**：菜单项集合随构建变体不同，本期一切「有没有这个菜单」的判断，以当前分支的菜单注册数据为准；父单文字与其它变体的差异只作为背景，不改变本期范围。
- 上线时间：父单未给出第一期日期（待确认）。
