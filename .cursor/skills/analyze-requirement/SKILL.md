# 需求分析 Skill

分析 TAPD 需求，结合后端接口变更，生成前端实现方案。

## 触发场景

- 用户提供 TAPD 需求链接
- 用户提供后端 MR 链接
- 用户询问如何实现某个功能需求

## 输入收集

### 必需输入
- **TAPD 链接**：需求/缺陷详情页链接

### 可选输入
- **后端 MR 链接**：接口变更的代码审查链接
- **截图/设计稿路径**：本地保存的截图或设计稿文件

## 执行流程

### 1. 切换到 Plan 模式

首先使用 SwitchMode 工具切换到 Plan 模式，以便进行交互式需求讨论。

### 2. 抓取 TAPD 内容

使用浏览器 MCP 工具访问 TAPD 页面：

```
1. 使用 browser_navigate 打开 TAPD 链接
2. 使用 browser_snapshot 获取页面内容
3. **必须滚动页面**获取完整的需求描述内容
4. 特别关注：
   - 需求标题和描述
   - **功能需求目录/列表**（必须完整提取所有功能点！）
   - 验收标准
   - **截图和设计稿**（非常重要！）
   - 关联的技术方案
```

**重要**：
- TAPD 中的截图通常包含关键的 UI 设计信息，必须仔细分析
- **必须完整遍历"功能需求"目录中的所有功能点**，不能遗漏

### 2.1 功能点完整性检查

在分析 TAPD 内容后，**必须**执行以下检查：

1. **列出所有功能点**：从需求描述中提取完整的功能点列表
2. **与用户确认**：在创建计划前，先向用户展示功能点列表，确认是否完整
3. **逐一分析**：确保每个功能点都在计划中有对应的实现方案

```markdown
## 功能点清单确认

我从 TAPD 需求中识别到以下功能点：

1. 功能点1：xxx
2. 功能点2：xxx
3. 功能点3：xxx

请确认是否完整，是否有遗漏？
```

### 3. 分析后端 MR（如有）

如果提供了后端 MR 链接：

```
1. 访问 MR 页面获取变更文件列表
2. 重点分析：
   - 新增/修改的 API 接口
   - 请求/响应数据结构变化
   - 接口路径和方法
3. 总结接口变更对前端的影响
```

### 4. 探索现有代码

使用 explore subagent 并行探索：

```
1. 相关模块的目录结构
2. 类似功能的现有实现
3. 复用组件和工具函数
```

### 5. 生成需求分析报告

按以下模板输出分析报告：

```markdown
# 需求分析报告

## 一、需求概述
- **需求名称**：[标题]
- **TAPD ID**：[ID]
- **需求类型**：新功能 / 功能优化 / 缺陷修复

## 二、功能点拆解
1. 功能点1
   - 描述
   - UI 变化
   - 交互逻辑
2. 功能点2
   ...

## 三、UI/设计分析
- 截图1 分析：[描述 UI 元素和布局]
- 截图2 分析：[描述交互流程]

## 四、接口变更影响
| 接口 | 方法 | 变更类型 | 前端影响 |
|------|------|----------|----------|
| /api/xxx | POST | 新增 | 需要新增调用 |

## 五、实现方案

### 5.1 涉及文件
- `src/views/xxx.vue` - 主视图修改
- `src/api/xxx.ts` - API 调用新增
- ...

### 5.2 实现步骤
1. [ ] 步骤1
2. [ ] 步骤2
3. [ ] 步骤3

### 5.3 复用组件
- 组件1：用途
- 组件2：用途

## 六、风险和注意事项
- 风险1
- 注意事项1
```

### 6. 交互式确认

生成报告后，与用户交互确认：

1. 功能点拆解是否准确
2. 实现方案是否合理
3. 是否有遗漏的细节

根据反馈调整方案，直到用户满意。

## 最佳实践

### 截图分析要点

1. **标注信息（最容易遗漏！）**：
   - 截图中的**箭头、线条、高亮标注**通常指向关键细节
   - **说明文字**：如"当xxx时，显示/隐藏xxx"等条件逻辑
   - 这些标注往往包含实现的关键逻辑，必须仔细阅读
2. **布局结构**：识别页面区域划分
3. **组件类型**：识别使用的 UI 组件（表格、表单、弹窗等）
4. **交互元素**：按钮、链接、输入框等的位置和功能
5. **条件显示逻辑**：哪些元素在什么条件下显示/隐藏
6. **状态变化**：不同状态下的 UI 差异

### 接口分析要点

1. **数据流向**：请求参数和响应数据的映射
2. **错误处理**：接口可能返回的错误码
3. **分页/加载**：列表类接口的分页逻辑
4. **权限控制**：接口是否有权限校验

### 代码探索要点

1. **目录结构**：遵循项目现有的文件组织方式
2. **命名规范**：遵循项目的命名约定
3. **复用优先**：优先使用现有组件和工具函数
