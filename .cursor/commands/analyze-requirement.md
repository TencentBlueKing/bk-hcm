## 使用说明

分析 TAPD 需求，结合后端接口变更，生成前端实现方案。

### 调用方式

```
/bk-hcm/analyze-requirement <TAPD链接> [后端MR链接]
```

示例：
```
/bk-hcm/analyze-requirement <TAPD需求链接>
/bk-hcm/analyze-requirement <TAPD需求链接> <后端MR链接>
```

### 附加截图

如果 TAPD 中的截图无法直接访问，可以：
1. 将截图保存到本地
2. 在对话中附上截图路径或直接粘贴图片

---

## 执行流程

### 1. 解析参数

从 `$ARGUMENTS` 中解析：
- 第一个参数：TAPD 链接（必需）
- 第二个参数：后端 MR 链接（可选）

### 2. 切换到 Plan 模式

使用 SwitchMode 工具切换到 Plan 模式，进行交互式需求分析。

### 3. 抓取 TAPD 内容

使用浏览器 MCP 工具：
1. `browser_navigate` 打开 TAPD 链接
2. `browser_snapshot` 获取页面内容
3. **滚动页面**确保获取完整的需求描述
4. **提取完整的功能点列表**（如"1.xxx 2.xxx 3.xxx"）
5. 特别关注截图和设计稿

### 3.1 功能点完整性确认

**在创建计划前必须执行**：
1. 列出从 TAPD 中识别到的所有功能点
2. 向用户确认功能点列表是否完整
3. 确保每个功能点都纳入实现计划

### 4. 分析后端 MR（如有）

访问 MR 页面，分析：
- 新增/修改的 API 接口
- 请求/响应数据结构
- 接口路径和方法

### 5. 探索相关代码

使用 Task 工具并行探索：
- 相关模块的目录结构
- 类似功能的现有实现
- 可复用的组件和工具

### 6. 生成分析报告

输出结构化的需求分析报告：

```markdown
# 需求分析报告

## 一、需求概述
- 需求名称、TAPD ID、需求类型

## 二、功能点拆解
- 功能点列表和描述

## 三、UI/设计分析
- 截图分析和 UI 细节

## 四、接口变更影响
- 接口列表和前端影响

## 五、实现方案
- 涉及文件、实现步骤、复用组件

## 六、风险和注意事项
```

### 7. 交互式确认

与用户反复确认和调整方案，直到满意。

---

## 注意事项

1. **必须关注截图**：TAPD 中的截图包含关键 UI 信息
2. **功能点完整性**：必须提取并确认所有功能点，不能遗漏
3. **滚动页面**：TAPD 需求描述可能较长，需要滚动获取完整内容
4. **接口影响分析**：后端变更如何影响前端实现
5. **遵循项目规范**：参考现有代码的风格和结构
6. **任务拆分合理**：每个任务应该是可独立完成的单元
