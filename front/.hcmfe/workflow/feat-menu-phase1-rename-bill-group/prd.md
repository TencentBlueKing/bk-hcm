## 一、背景与目标

现网 HCM（`<DEPLOY_HOST>`）左侧导航要按四期方案整合，本期是第一期，只做两件事：两个一级菜单更名，以及把「账号管理」下现有的账单类入口收进一个二级分组。

- 「资源管理」「账号管理」这两个名称与总规里的「业务资源」「资源运营」不一致，用户按新口径找不到入口。
- 「账号管理」下现在可进入的是「云账号管理」和「云账单管理」，它们是可点击菜单而不是分组。本期把它们收进二级分组「云账单管理」。
- 「云账号管理」是一个带「一级账号」「二级账号」页签的页面，两个页签的查看权限不同。本期把两个页签拿出来直接作为菜单项，用户从侧栏一步进入，不再经过页签切换。
- 先把名称与账单类入口的层级对齐总规，后面三期在这个结构上继续加菜单。
- 目标用户：已登录、且原本就能看到这些菜单的现网用户。
- 本期不新增查询、不新增接口、不新增业务数据；一级账号、二级账号列表由原页签内容独立成页，内容不变。

## 二、用户故事

1. 作为原来能看到「资源管理」的登录用户，我想要在原位置看到一级菜单「业务资源」，以便按总规名称进入原来的业务资源功能，且其下子菜单仍在。
2. 作为原来能看到「账号管理」的登录用户，我想要在原位置看到一级菜单「资源运营」，以便按总规名称进入原来的账号与账单功能。
3. 作为原来能看到「账号管理」下云账号管理或云账单管理的登录用户，我想要在「资源运营」下的二级分组「云账单管理」里看到一级账号、二级账号、云账单管理这几个菜单，以便从侧栏直接进入对应列表，而分组标题本身不打开页面。
4. 作为通过旧书签或旧页面地址进入的用户，我想要仍然落到我有权限的账号列表或原来的页面，以便更名和拆分之后已保存的入口不用更换。
5. 作为没有二级账号查看权限的普通用户，我想要仍能在侧栏找到「二级账号」，点进去看到明确的无权限提示和申请入口，以便自行申请，而不是一张没有说明的空表格。
6. 作为没有一级账号权限的非管理员，我不需要看到「一级账号」菜单。

### F-001 资源管理更名为业务资源

- **输入**：用户打开左侧导航。
- **行为**：该一级菜单显示为「业务资源」；其下二级分组与三级菜单项的名称、层级、相对顺序全部不变。
- **本期保持的现有结构**：
  - 分组「资源」：主机、硬盘、VPC、子网、弹性 IP、网络接口、路由表、安全组、负载均衡、证书托管
  - 分组「其他」：单据管理、任务管理、操作记录
  - 分组「账号」：云账号管理
  - 分组「回收站」：回收站
- **边界**：
  - 只改这一级的显示名称。
  - 「镜像」不在侧栏菜单中，本期不把它加进菜单。
  - 「业务资源 → 账号 → 云账号管理」与「资源运营」下的一级 / 二级账号是不同入口，本期只改一级名称，不搬迁、不合并业务资源这一处。
- **异常**：用户原本看不到「资源管理」→ 更名后仍看不到「业务资源」。

### F-002 账号管理更名为资源运营

- **输入**：用户打开左侧导航。
- **行为**：该一级菜单显示为「资源运营」，它与其它一级菜单的左右顺序不变。
- **异常**：用户原本看不到「账号管理」→ 更名后仍看不到「资源运营」。

### F-003 新增二级分组「云账单管理」

- **输入**：用户进入「资源运营」。
- **行为**：
  1. 侧栏出现二级分组标题「云账单管理」。
  2. 本期每一个二级都只是分组名称，形态与「业务资源」现有分组一致，点击分组不打开页面。
  3. 可进入的页面只放在分组下的三级菜单项。
- **边界**：分组名称就是「云账单管理」，与其下同名的三级菜单项并存；「资源运营」下不保留可点击的二级菜单项。
- **异常**：用户看不到该分组下任何三级菜单 → 不因新增分组而获得新页面。

### F-004 分组下的三级菜单项

- **输入**：用户查看「资源运营 → 云账单管理」。
- **行为**：
  1. 分组下依次为「一级账号」「二级账号」「云账单管理」三个三级菜单项。
  2. 「一级账号」「二级账号」替代原「云账号管理」菜单项，分别直接打开原页签里的一级账号列表、二级账号列表；列表的搜索、列、详情侧滑与「录入一级账号 / 创建二级账号」按钮与原页签一致。
  3. 原「云账号管理」页面的标题与页签切换不再保留。
  4. 「云账单管理」名称不变，进入后打开的仍是原来的页面；它页面内部的页签不是侧栏菜单，仍留在页面里。
  5. 在「录入一级账号」「创建二级账号」页面时，侧栏分别高亮「一级账号」「二级账号」。
- **边界**：父单列出的第三个账单类菜单项不在本分支的菜单注册范围内（该菜单项在不同构建变体下存在与否不一致），本期不新增；三级「云账单管理」与二级分组同名，两处都保留。
- **异常**：用户没有某一项的查看权限 → 看不到那一项（见 F-008）。

### F-005 没有其它子菜单时不另起分组

- **行为**：
  1. 按本分支的菜单注册数据，「账号管理」下没有这两项以外的可见子菜单。
  2. 因此「资源运营」下只有「云账单管理」一个二级分组，不把空层级留成可点击菜单。
  3. 若现网实际另有可见子菜单，不为它们保留可点击的二级菜单项，而是按「业务资源」的形式另起二级分组名称，再在分组下挂三级菜单项。
- **边界**：不把其它子菜单直接塞进「云账单管理」分组，除非它们本就属于账单这一类；隐藏的非菜单页面不升成侧栏菜单。
- **异常**：原来不可见的入口 → 仍然不可见。

### F-006 一级菜单顺序不变

- **行为**：一级菜单从左到右的顺序与现网一致（现网顺序：资源管理、服务请求、资源接入、账号管理、平台管理），仅把其中两个显示为「业务资源」「资源运营」。
- **边界**：不新增、不删除、不重排其它一级菜单。
- **异常**：某个一级菜单因权限本就不显示 → 本期不改变它的显隐。

### F-007 旧入口继续可用

- **行为**：
  1. 原「云账号管理」地址（旧书签，以及顶栏「资源运营」的默认入口）：有一级账号查看权限 → 落到一级账号列表；否则 → 落到二级账号列表，再由二级账号的权限规则决定能否查看。
  2. 原「录入一级账号」「创建二级账号」页面地址 → 落到对应的新建页。
  3. 其它旧地址（云账单管理及其页签）→ 打开原来的页面。
  4. 跳转时保留原地址上的查询参数。
- **边界**：跳转是静默的，不出跳转提示页，也不下线旧地址。
- **异常**：两类账号权限都没有 → 落到二级账号，按 F-008 进入无权限页。

### F-008 一级 / 二级账号的查看权限

- **输入**：用户进入「资源运营」，或直接访问一级 / 二级账号的列表地址。
- **行为**：
  1. 「一级账号」面向管理员，沿用原一级账号页签的查看权限（一级账号查看）：没有权限时菜单不显示；直接访问地址进入无权限页，页面说明「该功能面向平台管理员，属于管理员的权限，不支持自助申请，如需使用请联系管理员授权」，**不显示「申请权限」按钮**。
  2. 「二级账号」面向普通用户，使用二级账号查看权限（账号-二级账号查看，只要对任意一个二级账号有查看权限即视为有权限）：**无论有无权限菜单都显示**；没有权限时点击菜单或直接访问地址，进入带「申请权限」入口的无权限页，由用户自行申请。
  3. 无权限页沿用现有的权限申请页；只为一级账号补充「联系管理员授权」说明，二级账号沿用已有说明。
  4. 由于「二级账号」始终显示，「云账单管理」分组始终可见。
- **边界**：
  - 二级账号列表展示哪些账号仍由后端按账号实例过滤，本期不改变数据范围。
  - 原二级账号页签没有前端查看校验：零权限用户看到的是一张没有提示的空表格。本期改为进入无权限页引导申请，属于前端表现调整，数据权限不变。
  - 「云账单管理」权限表现不变：沿用云账单查看权限，只隐藏菜单；直接访问不拦截，页面能打开但数据接口由后端拒绝。
  - 「录入一级账号」「创建二级账号」页面的权限规则不变。
- **异常**：权限数据尚未加载完成 → 等待权限加载后再判定，不出现先显示页面再跳走的闪烁。

## 四、业务规则

- **R-001**：本期所有二级都只是分组名称，点击不打开页面，形态与「业务资源」现有分组一致。
- **R-002**：二级分组与其下三级菜单项同时使用「云账单管理」这一名称。
- **R-003**：调整范围仅限本分支「账号管理」侧栏中真实注册的「云账号管理」（拆为一级账号、二级账号）与「云账单管理」；父单列出的第三个账单类菜单项不在本分支注册范围内，本期不新增。菜单项集合随构建变体不同，核对基准一律是当前分支的菜单注册数据，不按父单文字推断。
- **R-004**：「资源管理」只改一级名称，其下「资源 / 其他 / 账号 / 回收站」四个分组及内部菜单项不动。
- **R-005**：一级菜单左右顺序冻结。
- **R-006**：旧页面地址与书签必须继续可用：原「云账号管理」地址按「先一级、后二级」的权限顺序分流，原新建账号页地址落到对应新建页，其它旧地址打开原页面。
- **R-007**：本期没有跳转提示页，也没有菜单下线等待期。
- **命名规则**：只使用「业务资源」「资源运营」「云账单管理」「一级账号」「二级账号」以及业务资源下原有分组名 / 菜单名，不使用别名。「资源运营」下不再出现「云账号管理」；「业务资源 → 账号 → 云账号管理」是另一处入口，保持不变。
- **权限规则**：沿用现有权限项，不新增、不合并权限项；一级账号、二级账号各用原来就存在的一级账号查看、二级账号查看权限；无权限用户不得通过新分组或新菜单看到原本不可见的数据。

## 五、非功能需求

- **性能**：本期不新增查询，不单列响应时间、并发与容量指标。
- **安全与权限**：数据权限与调整前一致；一级 / 二级账号在前端的拦截只会让无权限用户看不到入口，不会让任何人看到更多数据。
- **兼容性**：浏览器范围与现网一致；旧页面地址保持可用（按 F-007 落地），等价于入口向后兼容。
- **可用性**：沿用现网导航可用性，不单列 SLA。
