# feat-clb-exclusive-cluster-mgmt 测试清单

> 工作流: `feat-clb-exclusive-cluster-mgmt`
> 关联文档: [prd.md](./prd.md) / [design.md](./design.md) / [api.md](./api.md) / [coding.md](./coding.md)
> 需求单: 独占集群管理页面

## 验证范围

- 功能边界: 资源接入-负载均衡双入口（负载均衡 / 独占集群）、独占集群列表与筛选、单条/批量分配到业务，对应 AC-001~AC-005。
- 不在范围: 后端同步与表结构、购买独占型规格、单据展示、CLB 列表实例规格字段（兄弟迭代 `feat-clb-list-spec-field`）、CLB 详情独占集群字段、容量管理菜单。

## 测试环境

- 前端入口: `<测试环境「资源接入 → 负载均衡」列表页，地址由执行人在测试时确认>`
- 测试账号: `<test_account>`
- 数据准备:
  - **接口未上环境**：`load_balancers/exclusive_clusters/{list,assign/bizs}` 在 PR #2078 只有契约文档，后端接口层还在兄弟单。仓库里**没有 mock**（提交前已删除），真实环境下列表就是 404 + 空表格。
  - 因此要验列表相关用例，必须用 devtools 的响应改写（Network → Override content）给 `exclusive_clusters/list` 造返回：`data.details` 至少 3 行（1 行 TGW 有 `max_conn`、1 行 STGW `max_conn: null`、1 行 `bk_biz_id` 为真实业务 ID 代表已分配），其余行 `bk_biz_id: -1`；`count` 请求（`page.count: true`）单独返回 `data.count`。
  - 造数据时每行的 `account_id` 要填**左侧树选中的那个账号**，否则分配弹窗的目标业务下拉本就该为空（下拉是按行的 `account_id` 取业务）。
  - 不改写响应时能验的只有 P0-01 / P0-02 / P0-03 / P0-04（入口、URL、请求次数与入参）和 P1-01；其余列表/分配用例标 Skipped 并注明「等后端上环境」。
  - 分配用的目标业务：该账号有管理权限的业务至少 1 个。
  - 本项目前端无单测底座，`covered-by` 一律留空，全部为人工点。
